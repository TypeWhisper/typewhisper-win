## Scope and interpretation

This compares **both the previous Windows application and the Mac application** with the new WinUI host, across the complete application surface and plugin inventory. It is a source-backed implementation inventory, not a claim that every legacy feature was retested or that all Mac features must ship on Windows.

Audited snapshots:

- Historical WinUI source-audit baseline: `ff77f43a129e2ba9055699c3a3da7af1dfb65cce`, branch `seofood/release-1.1`.
- Previous Windows: `e18adcd51a2e80f904a55ad2aa2282dab1f54296`, local checkout `F:/typewhisper/typewhisper-win`.
- Mac: `357fe6f70a463ae376e485e5c1ef4f4d24db2c1e`, local checkout `F:/typewhisper/typewhisper-mac`.

The comparison follows entry points, service consumers, settings callbacks, persistence and processing calls. A service in Core, a linked source file, an SDK interface or a rendered setting is not enough to count as connected. Conversely, a `Prototype` filename does not imply a fake feature: dictionary editing and history reading are connected despite their names.

Status applies to **WinUI**: **Connected** means the stated runtime path exists; **Partial** means a useful subset exists with the listed gaps; **Preview** means sample/session behavior; **Missing** means no corresponding WinUI integration was found; **Decision** means platform or product scope needs an explicit choice. None means release acceptance is complete. Reference columns describe source implementations at the pinned snapshots, not fresh end-to-end validation. “Not found” is limited to this audit.

## Findings that change the release plan

1. The implemented core is real dictation with two providers, dictionary/snippets, basic history, audio preferences, hotkeys and package management. Real workflow, file, recorder, setup and backup subsets are now connected; licensing, sync and other gaps remain explicit below.
2. Recording mode, native English translation, text normalization/formatting, output, retention and quiet-clip policy now affect runtime. Ordered language hints are persisted and gated by an explicit SDK capability; neither connected provider currently advertises this capability. Generic LLM translation remains open.
3. The portable runtime now owns transcription and LLM capabilities and exposes scoped calls to WinUI. Groq uses that owner; NVIDIA/CTC retain their existing local owner. Manual and automatic Website/App/Global workflows consume LLM calls. Portable text processors are connected; generic action registry/controller support is wired into explicit Review actions with shutdown drain. Selected-text workflow shortcuts are connected; workflow-specific dictation shortcuts and memory remain open. Opt-in local spoken feedback is committed in `ff3c44b`; restart persistence passed; automatic-dictation acceptance remains open.
4. The legacy Windows pipeline and Mac pipeline both have substantially more stages than WinUI. WinUI now uses the Core ordering for built-in text steps, with snippets before dictionary corrections and regression cases. Saved spoken-command profiles and target-app formatting now run before snippets. Required workflow LLM processing runs at Core priority 300 before snippets; portable text processors share deterministic priority ordering. A separate translation-handler stage remains open.
5. 7. Green headless CI establishes portable logic coverage, not WinUI compilation, real cloud service acceptance, shipped package availability, accessibility or release readiness. CodeRabbit reports success while **skipping review because this is a draft**.

## Recommended delivery order and completion criteria

This is a proposed implementation order, not an approval to silently remove reference features. Each remaining area must be implemented, explicitly deferred, or documented as platform-specific before the draft becomes release-ready.

1. **Make visible settings truthful.** Insertion/review and history saving are connected. Recording mode, native task, text preferences and retention now connect; language hints already persist behind SDK capability checks; continue with remaining preview controls. Acceptance: changing each real setting changes the next operation and survives restart; unavailable settings cannot imply protection they do not provide.
2. **Complete the shared processing and job layer.** Built-in and portable processor ordering, LLM workflows, cancellation and minimal provenance are connected. Verify the wired action UI and finish remaining capabilities and durable recovery; complete the remaining native recovery and action acceptance. Acceptance: deterministic pipeline/failure/cancellation tests plus a real dictation saved with accurate provenance.
3. **Complete workflows.** CRUD, all eight templates, model/provider choice and Website/App/Global matching are connected. Selected-text shortcuts are committed through `d55ec0d` with isolated Notepad/fixture native acceptance; real-provider acceptance remains open. Workflow-specific dictation shortcuts, broader overrides and failure retry remain open. Acceptance: one local and one cloud workflow complete from trigger to result, including failed requests without losing original text.
4. **Connect files and recorder.** Reuse platform capture/decoder services behind portable job decisions; output formats, progress/cancel, history/audio, real exports and watch folders. Acceptance: mic/system capture produces playable files; real media produces verified text/timings; cancel/retry and restart recovery are tested.
5. **Finish history and personal data.** Edit/delete/export, raw/final/context, audio lifecycle, retention, correction learning, usage statistics, backup and sync. Acceptance: restart/failed-write/conflict/deletion tests and category-based backup round trips using isolated data.
6. **Scale plugins and delivery.** Capability-driven settings/contributions, remaining selected providers, lifecycle/dependencies and real v2 publishing. Acceptance: install/configure/use/update/restart/uninstall/reinstall through published packages, plus plugin-owned tests. No host edit should be needed merely to add another compatible provider.
7. **Complete the application and release gates.** Real onboarding/account/update/autostart, localization, API/CLI/shell integration, chosen Mac additions and Windows support policy. Acceptance: actual WinUI build/release install, x64/ARM64 as claimed, accessibility/DPI/device/editor checks, performance measurements and upgrade/uninstall/rollback policy.

The ordering has dependencies: durable jobs serve dictation, files, recorder and automation; a generic capability host serves workflows and additional plugins; real usage and history feed the dashboard. Adding providers alone does not close these gaps.
