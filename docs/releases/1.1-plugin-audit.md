# Windows 1.1 portable plugin audit

Audited on 2026-09-10 against source commit `62ec0d1469ecf03a1da820fb7c85ebcd46a9b189`, the deployed [portable catalog](https://typewhisper.github.io/typewhisper-win/plugins-v2.json), and the `gh-pages` versions of both catalogs. The deployed v2 document matched the repository copy. This is a source and published-package audit; it does not establish provider API behavior or ARM64 hardware execution.

## Published portable packages

The legacy catalog contains 39 user-facing plugins. The portable catalog contains three, all requiring host version 1.1.0 or later:

| Plugin | Version | Advertised architectures | ZIP bytes | SHA-256 |
| --- | --- | --- | ---: | --- |
| NVIDIA Parakeet (`sherpa-onnx`) | 1.1.1 | x64, ARM64 | 50,968,743 | `d07958a26061e18b7e01c30c4f48953c700954ca15adc3995d66fc6532b51a8a` |
| Groq | 1.1.1 | x64 | 19,407 | `f8ea34876ffa247893010dc9d02ad625b14a921ef3ec770f1a714143e2d0bf97` |
| Deepgram | 1.1.2 | x64 | 14,744 | `8ec08f959145f0ba31dd6bc491381c4f8e77242469ce3b64b24b3b1b7c280d20` |

Downloaded the assets referenced by the catalog from releases [plugins-v2-categories-20260908](https://github.com/TypeWhisper/typewhisper-win/releases/tag/plugins-v2-categories-20260908) and [plugins-v2-streaming-20260908](https://github.com/TypeWhisper/typewhisper-win/releases/tag/plugins-v2-streaming-20260908). All three sizes and hashes match. Root manifests agree with catalog IDs, versions and minimum host versions. Their dependency manifests target .NET 10, and the plugin assemblies have no direct references to PresentationFramework, PresentationCore, WindowsBase or System.Windows.Forms.

The Parakeet ZIP name ends in `win-x64`, but it includes both native architectures. PE headers confirm AMD64/ARM64 for the corresponding ONNX, sherpa C API and sherpaort DLLs, including the bundled CTC dependency's ONNX runtime. The package contains `Dependencies/com.typewhisper.parakeet-ctc/manifest.json`, marked as an internal dependency. This explains the 40 source projects versus 39 user-facing plugins; CTC is not a missing standalone catalog entry.

Groq and Deepgram are filtered out on ARM64 by the current catalog metadata. Their managed portable builds alone do not justify changing that support declaration without validation. Earlier x64 Parakeet download/model/inference acceptance is recorded in [the Daily validation notes](1.1-daily-validation.md); this audit did not repeat inference or authenticated cloud calls.

## Migration inventory

Five user-facing projects have both `net10.0` and `net10.0-windows` targets and a `portable.proj`: the three published plugins, plus **Filler Words** and **Obsidian**. Those two have portable build plumbing but no v2 catalog entry. Packaging, host loading, settings/actions and architecture support still need acceptance before publication.

The remaining 34 user-facing projects have only `net10.0-windows` targets and no portable project entry point:

## Publication gap and next steps

`.github/workflows/publish-plugins.yml` currently builds the legacy `net10.0-windows` output, stages the normal manifest and updates `plugins.json`. It does not publish `plugins-v2.json`. The portable entry points and `eng/PortablePlugin.targets` provide build/copy plumbing, but the checked-in workflow does not turn those outputs into a maintained v2 catalog. Legacy publication must continue independently.

1. Validate and package Filler Words and Obsidian as the next two portable candidates.
2. Add a dedicated v2 publication path that checks portable manifests, dependencies, host compatibility, hashes, sizes and actual architecture support before updating the separate feed.
3. Migrate the remaining 34 projects in bounded groups, including their settings UI and native/script dependencies where applicable; a target-framework change alone is insufficient.
4. Validate Groq and Deepgram on ARM64 before widening their catalog metadata. Keep native ARM64 inference as a separate hardware requirement.

No plugin package, catalog or release was modified during this audit. Catalog parity remains open: **3 published + 2 prepared + 34 awaiting migration = 39 user-facing plugins**.
