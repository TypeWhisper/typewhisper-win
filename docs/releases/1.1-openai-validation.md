# OpenAI / ChatGPT 1.1 development acceptance

Validated on September 10–11, 2026, using the independent portable plugin `1.1.4` and host contract `1.1.2`. This is development acceptance, not a published release or complete macOS feature-parity claim.

## Live provider checks

The probe loaded the installed development package through `PortablePluginPackage` with the user's separately configured API and ChatGPT credentials. Test settings and refreshed credential values were isolated from the running app; secrets were not written into logs. Inputs were short synthetic meeting-planning sentences. German audio was synthesized through OpenAI; English audio used a local Windows voice.

| Capability | Observed result |
| --- | --- |
| API configuration and catalog | Key validation succeeded; account models were fetched. |
| ChatGPT catalog | Account model list was fetched successfully. |
| Text translation | Both API GPT-4o Mini and ChatGPT GPT-5.5 returned the expected English sentence. |
| Additional text models | GPT-5.5 through the API and GPT-6 Astra through ChatGPT returned the expected answer. After the compatibility correction, GPT-6 Astra through the API also returned the expected answer. |
| German file transcription | GPT Transcribe, Whisper 1, GPT-4o Transcribe and GPT-4o Mini Transcribe reproduced the entire test sentence correctly. |
| English file transcription | GPT Transcribe reproduced the entire sentence correctly. |
| Whisper 1 audio translation | Failed initially with HTTP 400 when `language=de` was supplied. Omitting the source-language field succeeded, including a subsequent call through the corrected plugin with compressed input. |
| GPT Live Transcribe | Returned all words; inserted a sentence break before “Und”. Thirteen partial events and one final event; 666 ms from finalization to completion in this run. |
| GPT Realtime Whisper | Returned the sentence correctly. Twelve partial events and one final event; 517 ms from finalization to completion. |
| Speech playback | Marin synthesis and playback completed. A Cedar playback stopped successfully, with the stop call returning in 3 ms. This verifies playback state, not a listening-quality assessment. |
| Microphone-to-app dictation | Marco dictated the requested sentence. History confirmed engine `openai`, model `gpt-transcribe`, language `de`, 5.33 seconds, and identical raw/final text. |
| Microphone-driven live preview | After enabling the global Live transcription option, Marco repeated the GPT Live Transcribe dictation and confirmed that the live preview worked. |

The microphone sentence was “Heute besprechen wir die Ergebnisse und legen die nächsten Schritte fest.” These short checks do not establish long-session accuracy or latency guarantees.

## Corrections prompted by acceptance

- Omit the source-language field for audio translation; the endpoint returns English. See the [translation request contract](https://developers.openai.com/api/reference/resources/audio/subresources/translations/methods/create).
- Route GPT-6 Astra through Responses, expose its supported reasoning levels and omit temperature. The old GPT-5-only routing produced an HTTP 400 for Astra through the API. See [model guidance](https://developers.openai.com/api/docs/guides/latest-model) and [Astra capabilities](https://developers.openai.com/api/docs/models/gpt-6-astra).
- Remove GPT-Live and legacy instruct models from the text-completion selector because they target other request contracts.
- Preserve the narrow WAV retry when a media-probe error is sanitized, and dispose the completed transcription response.

The corrected provider suite passed 73 tests. Earlier complete headless validation passed 2,385 tests; 120 targeted legacy OpenAI/TTS tests additionally passed in Debug. The legacy Release test build was blocked before execution by missing ARM64 MSVC files required by WhisperCpp packaging.

## Remaining acceptance boundaries

- Long microphone sessions, non-default physical output-device routing and listening quality are not established by these checks.
- Marco's first GPT Live Transcribe microphone check delivered text without a preview. Inspection found the global overlay preference `LiveText=false`, which also prevents the host from opening a preview stream during recording. The Appearance → Live transcription switch was enabled and its persisted value verified. Marco then repeated the dictation and confirmed the preview worked; no plugin change was needed for this observation.
- OAuth browser callback, forced token expiry and reauthentication were not exercised in this live run. The already configured login was used successfully; persistence/error behavior has fake-transport coverage.
- Version-to-version plugin updates and side-by-side installed-generation checks remain pending. Same-version development restaging is not an update test.
- File-based buffered GPT Transcribe preview from macOS is not implemented; realtime preview uses the live models.
- No release, catalog publication or production-profile migration was performed.
