# WinUI Daily validation: update channels and on-demand plugins

## Build and scope

Validated the PR #452 candidate from GitHub Actions run 34461775686 (PR merge commit `43b98502d1d761014ed0acf268b15cbb7bbcf3e1`, version `1.1.0-daily.20260910.8`). Both x64 and ARM64 release packaging passed. This candidate has not been published as a Daily release.

## Package measurements

ARM64 setup: 222,263,045 bytes before, 159,675,920 bytes after (212.0 to 152.3 MiB, approximately 28% smaller). The previous comparison candidate is `1.1.0-daily.20260910.5`.

x64 setup: 230,632,336 bytes before (published Daily `.6`), 167,570,067 bytes after (219.95 to 159.81 MiB, 60.14 MiB / 27.3% smaller). Its candidate payload is 120.87 MiB compressed for the app/runtimes plus 35.32 MiB for the CLI. SHA-256 verification passed for the x64 candidate, setup and full update package.

The compressed candidate payload contains 114.94 MiB of app/runtime files and 33.73 MiB of CLI files, with no bundled plugin directory. Previous bundled plugins occupied 49.95 MiB compressed. Removing the WinForms dependency also reduced the app/runtime payload.

SHA-256 verification passed for the downloaded ARM64 candidate and setup. Hashing the decompressed files found 186 CLI files identical to app-root files: 86.15 MiB unpacked / 33.56 MiB compressed. These are potential packaging savings; the CLI currently needs a complete independent runtime when installed and must not simply lose these files.

## Runtime cleanup follow-up

Run 34463977594 validated version `1.1.0-daily.20260910.10`, PR merge commit `87f310ca1174ac376d71c7a3bf2f33bcddcb6ea3` (branch head `5a603307`). Both WinUI architecture packages and the portable logic suites passed. This candidate remains unpublished.

The x64 setup is now **79,553,777 bytes / 75.87 MiB**, down from the intermediate 159.81 MiB above (52.5% smaller) and the original 219.95 MiB. Its candidate ZIP is 72.35 MiB: 72.08 MiB of app/runtime payload and 0.20 MiB of CLI payload. SHA-256 verification passed for the downloaded candidate, setup and full update package. Candidate validation also passed locally after extraction.

The WinUI host references a single-target portable SDK built from the same shared SDK sources. This prevents restore from selecting the legacy WPF SDK target. The legacy SDK and plugin packages remain unchanged. WinUI now references the required Windows App SDK components rather than the umbrella package, removing unused host ONNX, DirectML and AI payloads. The tray bridge assembly is restored separately to avoid reintroducing its old umbrella dependency.

CLI publishing records identical runtime files in a SHA-256 manifest and removes their duplicate copies from the download. Installation reconstructs a complete independent CLI from verified app-root files. It does not depend on the app directory after installation. The CLI remains an optional install from Advanced; it has not been converted into a plugin. The final candidate passed a real install, `--version`, `--help` and removal smoke test with an isolated destination and injected PATH storage; the real user PATH was unchanged.

23 CLI installation tests, 245 portable SDK/host tests and 11 packaging checks passed. The local development helper built and started the app; a synthesized WAV transcribed successfully through the installed Parakeet plugin, returning the expected sentence. Plugin-private ONNX remains available for actual inference.

The full-solution CI also exposed an AnyCPU build without a native architecture. Follow-up `6788a923` defaults unspecified WinUI builds to win-x64 and respects ARM64 or an explicit RID. Property evaluation was verified for both defaults; its full-solution CI rerun must pass before merging.
