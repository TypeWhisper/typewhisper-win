# WinUI Daily validation: update channels and on-demand plugins

## Build and scope

Validated the PR #452 candidate from GitHub Actions run 34461775686 (PR merge commit `43b98502d1d761014ed0acf268b15cbb7bbcf3e1`, version `1.1.0-daily.20260910.8`). Both x64 and ARM64 release packaging passed. This candidate has not been published as a Daily release.

## Package measurements

ARM64 setup: 222,263,045 bytes before, 159,675,920 bytes after (212.0 to 152.3 MiB, approximately 28% smaller). The previous comparison candidate is `1.1.0-daily.20260910.5`.

x64 setup: 230,632,336 bytes before (published Daily `.6`), 167,570,067 bytes after (219.95 to 159.81 MiB, 60.14 MiB / 27.3% smaller). Its candidate payload is 120.87 MiB compressed for the app/runtimes plus 35.32 MiB for the CLI. SHA-256 verification passed for the x64 candidate, setup and full update package.

The compressed candidate payload contains 114.94 MiB of app/runtime files and 33.73 MiB of CLI files, with no bundled plugin directory. Previous bundled plugins occupied 49.95 MiB compressed. Removing the WinForms dependency also reduced the app/runtime payload.

SHA-256 verification passed for the downloaded ARM64 candidate and setup. Hashing the decompressed files found 186 CLI files identical to app-root files: 86.15 MiB unpacked / 33.56 MiB compressed. These are potential packaging savings; the CLI currently needs a complete independent runtime when installed and must not simply lose these files.

## Windows 11 VM installer acceptance

On 2026-09-10, candidate `1.1.0-daily.20260910.22` from Actions run `34476111058` (PR #453 head `17d043ad`, packaged merge commit `7100aca3`) was tested in a fresh x64 Windows 11 Home 24H2 VM, OS build `26100.9445`, with 4 GB RAM. The setup SHA-256 was `3ba273686dfcd903cca844128019f76496ebd6cdbb6f50ea3267e2ed9772181a`. The test ISO carried both the current shared-runtime package and the earlier bundled-runtime candidate `.10`.

Setup detected the missing .NET 10 x64 runtime. Cancelling closed setup and returned to Explorer; restarting setup displayed the prerequisite prompt again. This confirms the visible cancellation/retry flow, but does not claim a registry or filesystem residue audit. Accepting installation downloaded Microsoft .NET Runtime 10.0.12 (x64). After Marco confirmed Windows UAC, runtime installation completed, TypeWhisper installed, and the Welcome wizard opened.

With the runtime present, rerunning setup offered Repair without requesting the prerequisite again. Repair completed and automatically reopened the Welcome wizard. After closing the installed wizard, the actual Velopack portable ZIP was extracted to a separate VM desktop directory; its launcher also opened the Welcome wizard without a prerequisite prompt. These observations supersede the earlier pending clean-machine and portable startup checks above. They do not establish profile isolation between installed and portable copies.

After restoring the clean VM snapshot, the bundled-runtime candidate `.10` installed and reached Welcome without a shared-runtime prerequisite. Setup was skipped for this migration-only test, and dictionary word `migrationprobe20260910` was saved and visibly verified. Running `.22` Setup detected the missing shared runtime, installed .NET 10.0.12 after Marco confirmed UAC, and explicitly offered an update from `.10` to `.22`. Accepting Update completed the setup-driven upgrade. The app opened again and retained the dictionary word (1 of 1 words). The unfinished wizard reappeared: Skip setup does not persist completion, so this test does not establish preservation of a completed wizard state.

This setup-driven migration does not verify the in-app updater's download, shutdown and restart flow; that acceptance check still needs two compatible published WinUI Daily releases. No transcription, ARM64 hardware execution or published Daily is claimed by these VM tests.
